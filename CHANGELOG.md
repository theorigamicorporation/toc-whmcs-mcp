All notable changes to toc-whmcs-mcp are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
the project uses [Semantic Versioning](https://semver.org/).

Entries below the first release heading are generated by
[release-please](https://github.com/googleapis/release-please) from
[Conventional Commits](https://www.conventionalcommits.org/). Do not edit them
by hand; fix the commit message convention instead.

A note on scope: a change to the safety classification in
`internal/registry/classification.go`, to a capability profile, or to the
confirmation protocol is a **behaviour change for operators**, not an internal
refactor. Mark those `feat:` or `fix:` with a clear scope, or `feat!:` when a
previously permitted operation becomes forbidden, so they surface in the
changelog rather than being hidden under `chore:`.

## 0.1.0 (unreleased)

Initial implementation. See the specification in `openspec/specs/`.

### Features

- MCP server exposing the WHMCS Admin API over stdio and Streamable HTTP.
- All 162 documented WHMCS actions reachable; 15 to 25 tools advertised
  depending on the profile.
- Capability profiles (`readonly`, `support`, `billing`, `admin`), read-only by
  default.
- Prepare/confirm protocol for consequential operations, with tokens bound to
  the exact arguments, expiring and single-use.
- Allowlist projection, secret and PII redaction, untrusted-content envelopes
  for customer-authored text.
- Bounded I/O: request timeouts, response size cap, clamped pagination, retries
  restricted to read-classified actions.
- Audit stream with per-operation IDs correlating confirmation issuance and
  consumption.
- Action registry generated from the vendor documentation, with hand-maintained
  safety classification and a generation-time gate on unclassified actions.
