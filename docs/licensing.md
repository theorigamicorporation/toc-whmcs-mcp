# Licensing and third-party material

This project is **AGPL-3.0**. Publishing under a copyleft licence means
asserting that everything in the repository can be redistributed under it, so
what comes *in* has to be checked, and so does anything we did not write
ourselves.

Short answer: every dependency is compatible, the notice obligations are met,
and the vendor documentation question is resolved by not carrying vendor prose
at all.

## Our licence

[LICENSE](../LICENSE) is the GNU Affero General Public License v3.0.
[NOTICE](../NOTICE) carries the copyright line, the third-party pointer, the
WHMCS trademark disclaimer and the operator's data-protection note.

AGPL rather than GPL because of the network clause: this is server software, and
someone can run a modified version and expose it to users over HTTP without ever
distributing a binary. Under plain GPL that would carry no obligation. Under
AGPL, offering it over a network to users obliges offering them the source.

It has to be AGPL **v3** specifically. One dependency is Apache-2.0, which is
compatible with GPLv3 and later but not with GPLv2, so a v2-era copyleft licence
was never an option.

### What we do owe

MIT, BSD and Apache-2.0 all require the copyright notice and licence text to
**travel with binary redistributions**. A compiled binary counts; so does a
container image.

That obligation is met by generating `THIRD_PARTY_LICENSES.md` and shipping it
in the release archives (`.goreleaser.yaml` includes it in every archive).

Apache-2.0 adds two conditions beyond attribution: propagate any `NOTICE` file
from the original, and state significant changes if you modify the source.
`santhosh-tekuri/jsonschema` ships no `NOTICE`, and we do not modify it, so
neither applies.

### Test and build-only dependencies

`testify`, `go-cmp`, `golang.org/x/net` (used by `cmd/docgen`, which is a
development tool and is not shipped), the linters and the CI actions are not
distributed. They carry no notice obligation. They are excluded from the
generated file deliberately, so it reflects what we actually ship rather than
everything that appears in `go.sum`.

### Container base images

The runtime image is `gcr.io/distroless/static-debian12` (Apache-2.0, plus
Debian base files under their own free licences: `ca-certificates`, `tzdata`,
`/etc/passwd`). The build stage uses `golang:alpine` but contributes nothing to
the final image beyond our own statically linked binary.

## Enforcement

This is checked, not assumed:

```sh
just licenses         # regenerate THIRD_PARTY_LICENSES.md
just licenses-check   # fail on a copyleft dependency or a stale file
```

`just ci` and the CI pipeline both run the check. Adding a dependency under a
non-permissive licence **fails the build** with an explanation, at the moment it
is added rather than during someone's legal review months later.

The allowlist is in `scripts/gen-licenses.sh`: permissive licences plus GPL,
LGPL, AGPL and MPL, all of which combine into an AGPL-3.0 work. What is excluded
is what cannot: GPL-2.0-only and EPL and CDDL are incompatible with GPLv3-family
copyleft, and source-available licences such as SSPL and BUSL are not free
software at all. Widening it is a legal decision, not a build fix.

### Adding a dependency

1. Add it, then run `just licenses`.
2. If it fails, do not widen the allowlist to make it pass. Find a permissive
   alternative, or get a decision from someone who can make one.
3. Commit the regenerated `THIRD_PARTY_LICENSES.md` with the change.

EPL and CDDL stay excluded because they are genuinely incompatible with
GPLv3-family copyleft, not because they are inconvenient.

## WHMCS documentation

`internal/registry/actions_gen.go` is generated by scraping
`developers.whmcs.com`. WHMCS publish those docs under "Copyright (c) WHMCS.
All rights reserved." There is no Creative Commons or other open grant, so
attribution alone would not confer a right to redistribute: crediting a source
and being licensed to copy it are different things.

Publishing under AGPL-3.0 asserts that everything here can be redistributed
under AGPL. That assertion cannot be made about text WHMCS wrote. So the
generator does not carry it.

**What is generated.** Action names, parameter names, types and requiredness.
These are facts about an interface. Facts are not copyrightable, and an API's
call signature is exactly the kind of thing you are entitled to describe in
order to interoperate with it.

**What is not.** Any vendor description longer than
`registry.LongDescriptionThreshold` (100 characters). `cmd/docgen` refuses to
emit those. It substitutes our own text from
`internal/registry/descriptions.go` where we have written one, and emits nothing
where we have not.

The threshold is a deliberately mechanical proxy for expressive room. Short
strings such as `"User ID"`, `"Format: MMYY"` and `"The note to add"` carry no
authorship: where only a handful of phrasings exist for a fact, expression
merges with the fact and there is nothing to own. Longer strings are somebody's
writing. The rule has to be mechanical because regeneration must stay
deterministic for `just gen-check` to mean anything.

All 65 vendor strings that exceeded the threshold have been replaced with our
own, which are written for an agent rather than for a developer reading a
manual: state the encoding and the constraint plainly, drop the worked PHP
examples an agent cannot execute anyway.

Two further measures:

- The generated file carries an attribution header naming WHMCS as copyright
  holder and pointing at the vendor page as authoritative, and
  `whmcs_describe_action` returns the same attribution in a `source` field
  beside each action's `documentation` URL.
- Test fixtures under `cmd/docgen/testdata/` are trimmed to the fragment the
  parser reads, which cut them from 92 KB to 24 KB.

A parameter with no description still carries its name, type and requiredness,
and still links to the vendor's own page. Adding an entry to
`descriptions.go` is how it gets an explanation back.

## Customer and personal data

Not a licensing question, but it sits next to one. This server mediates access
to customer personal data, and [LICENSE](../LICENSE) section 4 puts GDPR
obligations on operators: minimum-scope credentials, need-to-know access, no
sharing between environments, revocation when no longer needed.

The technical side of that is in
[the security model](security-model.md#data-minimisation): personal data
requires a per-call opt-in that is audited, and credentials are never returned
at all.
