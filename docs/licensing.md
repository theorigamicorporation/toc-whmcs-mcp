# Licensing and third-party material

This project is proprietary and closed. That makes what comes *in* worth
checking, because a dependency under the wrong licence would impose obligations
that conflict with shipping it closed.

Short answer: **no restrictions block proprietary distribution.** Every
dependency compiled into the binary is permissive. There is one notice
obligation, which is met, and one open judgement call about vendor
documentation, described at the end.

## Our licence

[LICENSE](../LICENSE): proprietary and confidential, all rights reserved, no
licence granted, no use for model training, GDPR obligations on operators.

### What we do owe

MIT, BSD and Apache-2.0 all require the copyright notice and licence text to
**travel with binary redistributions**. A compiled binary counts; so does a
container image.

That obligation is met by generating `THIRD_PARTY_LICENSES.md` and shipping it
in the release archives (`.goreleaser.yaml` includes it in every archive).

Apache-2.0 adds two conditions beyond attribution: propagate any `NOTICE` file
from the original, and state significant changes if you modify the source.
`santhosh-tekuri/jsonschema` ships no `NOTICE`, and we do not modify it, so
neither applies.

### Test and build-only dependencies

`testify`, `go-cmp`, `golang.org/x/net` (used by `cmd/docgen`, which is a
development tool and is not shipped), the linters and the CI actions are not
distributed. They carry no notice obligation. They are excluded from the
generated file deliberately, so it reflects what we actually ship rather than
everything that appears in `go.sum`.

### Container base images

The runtime image is `gcr.io/distroless/static-debian12` (Apache-2.0, plus
Debian base files under their own free licences: `ca-certificates`, `tzdata`,
`/etc/passwd`). The build stage uses `golang:alpine` but contributes nothing to
the final image beyond our own statically linked binary.

## Enforcement

This is checked, not assumed:

```sh
just licenses         # regenerate THIRD_PARTY_LICENSES.md
just licenses-check   # fail on a copyleft dependency or a stale file
```

`just ci` and the CI pipeline both run the check. Adding a dependency under a
non-permissive licence **fails the build** with an explanation, at the moment it
is added rather than during someone's legal review months later.

The allowlist is `MIT`, `BSD-3-Clause`, `BSD-2-Clause`, `ISC`, `Apache-2.0`, in
`scripts/gen-licenses.sh`. Widening it is a legal decision, not a build fix.

### Adding a dependency

1. Add it, then run `just licenses`.
2. If it fails, do not widen the allowlist to make it pass. Find a permissive
   alternative, or get a decision from someone who can make one.
3. Commit the regenerated `THIRD_PARTY_LICENSES.md` with the change.

Weak-copyleft licences (MPL, LGPL, EPL) are excluded on purpose. They are often
usable in a proprietary product with care around linking and modified-file
disclosure, but "with care" is not a property a build gate can verify, and this
is billing infrastructure rather than a place to be clever.

## The open question: WHMCS documentation

`internal/registry/actions_gen.go` is generated by scraping
`developers.whmcs.com`. Two things are worth being explicit about, because
neither is a settled question that a script can decide.

**What is copied.** Action names, parameter names, types and requiredness are
facts about an interface, and facts are not copyrightable. Parameter
*descriptions* are prose written by WHMCS, and they are reproduced verbatim in
the generated file and returned to callers by `whmcs_describe_action`.

**Where it stands.** Reading published API documentation in order to interoperate
with the product you license is the documented purpose of that documentation, and
this repository is private and internal. Nothing here is redistributed to third
parties or offered as a competing product. The risk is low.

It is not zero, and it is a legal call rather than an engineering one. Two
mitigations are in place already:

- Test fixtures under `cmd/docgen/testdata/` are trimmed to the fragment the
  parser reads: the title, summary and parameter tables. Site navigation,
  styling and marketing content are removed. That cut them from 92 KB to 24 KB
  and reduced the copied material to what the offline test genuinely needs.
- [LICENSE](../LICENSE) section 5 states that generated schemas derive from
  vendor documentation and remain subject to that vendor's terms, and disclaims
  affiliation.

If a stricter position is ever wanted, the available step is to drop the
`Description` field from the generated registry and keep only names, types and
requiredness. That removes the prose entirely at the cost of making
`whmcs_describe_action` much less useful to an agent, which is a real product
trade-off. It has not been done because the current position looks defensible;
raise it with legal if you disagree.

## Customer and personal data

Not a licensing question, but it sits next to one. This server mediates access
to customer personal data, and [LICENSE](../LICENSE) section 4 puts GDPR
obligations on operators: minimum-scope credentials, need-to-know access, no
sharing between environments, revocation when no longer needed.

The technical side of that is in
[the security model](security-model.md#data-minimisation): personal data
requires a per-call opt-in that is audited, and credentials are never returned
at all.
